# DhanView v0.7 release and security patch notes

## Unreleased — separate AI Coach workspace
- Moved the AI conversation off the main dashboard into a focused Coach screen while keeping the signed-in data loader and account scope unchanged.
- Replaced repeated per-answer charts with a compact report rail: key monthly metrics, an outflow donut, and expense-category bars.
- Kept planning prompts available as one-click entry points to the Coach; the prompt stays in page state and is not placed in the URL.
- Added a collapsed, responsive set of all six planning prompts inside the Coach, available during both new and ongoing chats; choosing a prompt only fills the draft and never sends it automatically.
- Added responsive layouts, a dashboard return control, system/light/dark theme support, and the Coach workspace to in-app release notes.

## Unreleased — conversational AI Coach
- Replaced the single-response composer with a responsive back-and-forth chat, quick-start prompts, a clear-conversation action, and loading/error states inside the chat.
- Kept up to 40 chat messages in page memory only; sent at most the latest 8 bounded turns with a follow-up question. The chat is not persisted to Supabase or browser storage.
- Added a visible disclosure that recent chat turns are sent to the configured AI provider to support follow-up context.
- Added Financial Engine visual summaries for cash flow, loans, investments, goals, and insurance. The figures and charts are rendered from saved app records, not generated by the AI.
- Added responsive and dark-theme styles for conversation bubbles, charts, and tables.

## Unreleased — debt guidance verification
- Supabase Edge Function logs confirmed the AI provider returned HTTP 503 while Supabase data and quota requests succeeded.
- Transient provider 429/5xx responses and connection timeouts now return deterministic engine guidance instead of failing the whole AI request; invalid provider credentials or endpoint configuration still surface a clear setup error.
- The AI Coach labels temporary provider outages clearly when it falls back to the Financial Engine.
- Added engine-calculated reserve timelines and single-loan prepayment illustrations to the minimized, debt-only AI fact payload in both the local gateway and Supabase Edge Function.
- The AI is instructed to use those supplied figures and assumptions verbatim, so a helpful planning answer no longer fails verification because deterministic scenario math was missing from its approved facts.
- Numeric verification now recognizes periods encoded in trusted fact paths, such as the 3- and 6-month reserve targets; unsupported response numbers remain rejected.
- Updated the coach eyebrow to FinBuddy AI Coach.

## Unreleased — transaction CSV import
- Added a browser-local CSV transaction importer to the monthly history view. CSV contents are not sent to an external parser or AI service.
- Corrected the import form's JSX fragment nesting that prevented webpack from parsing `TransactionCsvImport.tsx`.
- Added column mapping for dates, descriptions, amount/type, and separate debit/credit columns, plus a preview and explicit confirmation before saving.
- Imported rows are stored in the signed-in user's transaction table with `source = Imported`; matching saved rows are skipped to reduce duplicate imports.
- PDF parsing is deliberately not included in this release. Users can export a bank/card statement as CSV; PDF import requires a reviewed local parser and additional format validation.
- Files are limited to 5 MB and 3,000 transaction rows per import. No migration is needed.

## Unreleased — fact-grounded AI coach and demo playback
- The local Ollama proxy and Supabase Edge Function now require structured responses that cite existing financial fact paths; unparseable citations or numbers outside supplied facts trigger the deterministic engine fallback.
- The dashboard displays AI answers only when the gateway reports a successful grounding check. Older deployed gateways without that response marker fall back to deterministic guidance until redeployed.
- Added Copy response and Ctrl+Enter / Cmd+Enter prompt submission.
- Reworked the local demo renderer to capture continuous frames and prefer H.264 MP4 when the browser supports it, with WebM fallback. Re-render the video locally before playback; the earlier WebM contained only a few captured frames.
- Fixed the renderer server's missing-file error path so it does not attempt to send a second set of HTTP headers.

## Required deployment steps
1. Back up Supabase before changing schema.
2. If the original schema migration has not run, run `supabase/migrations/001_artha_v06.sql`.
3. Run `supabase/migrations/002_security_hardening.sql`.
4. Run `supabase/migrations/003_schema_alignment_and_rls.sql`.
5. Run `supabase/migrations/004_ai_required_fields.sql` to add/backfill the canonical loan and insurance fields read by the AI function.
6. In Supabase Edge Function secrets, set `ALLOWED_ORIGINS` to:
   `https://harishsarmav.github.io,http://localhost:3000,http://127.0.0.1:3000`
7. Deploy the Edge Function: `supabase functions deploy artha-ai`.
8. Install the committed lockfile with `npm ci`, then run `npm audit --audit-level=high` and `npm run build`.
9. Commit the regenerated `package-lock.json` and source changes, then push to `main` to trigger GitHub Pages deployment.
